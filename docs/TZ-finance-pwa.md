# Техническое задание: личное финансовое приложение (PWA)

## 1. Цель

Личное приложение для учёта доходов и расходов, контроля лимитов по категориям и ведения месячного бюджета. Используется одним пользователем. Устанавливается на домашний экран телефона как PWA.

## 2. Контекст использования

- Доходы (заработная плата и прочее) поступают в казахстанских тенге (KZT).
- Расходы совершаются в Испании в евро (EUR).
- Основная валюта учёта, бюджета и лимитов — евро.

## 3. Платформа и технологии

- Прогрессивное веб-приложение (PWA): веб-манифест, сервис-воркер, установка на домашний экран, полноценная работа без интернета.
- Адаптивный интерфейс, приоритет — мобильный экран (iOS и Android).
- Хранение данных: локально в браузере (IndexedDB). Серверной части и регистрации нет.
- Хостинг статических файлов: бесплатный (например, GitHub Pages или Cloudflare Pages).
- Язык интерфейса: русский.
- Стек выбирает исполнитель; предпочтительно простой и поддерживаемый (например, Vite + TypeScript, без тяжёлых фреймворков).

## 4. Функциональные требования

### 4.1. Операции
- Добавление, редактирование и удаление операции.
- Поля: тип (доход / расход), сумма, валюта (EUR / KZT), дата, категория, комментарий (необязательно).
- Для каждой операции хранится курс пересчёта и сумма в евро.
- **Покупка с позициями (чек):** операция-покупка может состоять из нескольких позиций. У каждой позиции: название продукта (из справочника, см. 4.12), количество, единица измерения (кг, г, л, шт, упаковка), цена за единицу, сумма и своя категория. Сумма покупки равна сумме позиций. Расходы по лимитам и отчётам учитываются по категории каждой позиции, а не по покупке в целом.
- Покупка без позиций (одна сумма на одну категорию) остаётся допустимой для быстрого ввода.
- Список операций с фильтрами по периоду, категории и типу.

### 4.2. Категории
- Справочник категорий расходов и доходов.
- Создание, переименование, архивирование категорий (удаление категории с операциями запрещено, вместо него — архивирование).
- Набор категорий по умолчанию задаётся при первом запуске и редактируется.

### 4.3. Лимиты
- Лимит задаётся на категорию на месяц в евро.
- Индикатор расхода лимита: остаток в евро и процент использования.
- Визуальное предупреждение при достижении 80 % и при превышении 100 %.
- Показатель «можно тратить в день»: остаток лимита, делённый на число оставшихся дней месяца.
- Сразу после сохранения расхода приложение показывает сообщение по его категории, например: «Продукты: осталось 143 € из 200 €, до конца месяца 12 дней, около 11,9 € в день».

### 4.4. Бюджет
- Месячный бюджет: плановые доходы и плановые расходы по категориям.
- **Копирование бюджета:** создание бюджета нового месяца на основе любого предыдущего (копируются категории, плановые суммы и лимиты) с возможностью последующего редактирования.
- Сравнение плана и факта по категориям за месяц.

### 4.5. Валюты и курсы
- Основная валюта — EUR.
- Курс KZT/EUR берётся по официальному курсу Национального банка Республики Казахстан на дату операции.
- Курс можно скорректировать вручную (если фактическая конвертация прошла по другому курсу). Ручной курс помечается в интерфейсе.
- Без интернета операция сохраняется без курса со статусом «курс не определён»; при следующем подключении курс подтягивается автоматически.
- Полученные курсы кэшируются локально.
- **Риск для проверки:** публичный источник курсов Нацбанка может не разрешать прямые запросы из браузера (ограничение CORS). Исполнитель должен проверить это на раннем этапе и, если запрос блокируется, предложить решение (например, небольшая облачная функция-прокси) до начала основной разработки.

### 4.6. Отчёты
- Итоги за месяц: доходы, расходы, баланс в евро.
- Расходы по категориям (диаграмма и таблица).
- Динамика по месяцам.

### 4.7. Резервное копирование
- **Выгрузка:** экспорт всех данных (операции, категории, лимиты, бюджеты, курсы, настройки) в один файл JSON. Имя файла содержит дату, например `finance-backup-2026-10-11.json`. По возможности использовать системное меню «Поделиться» (Web Share API), чтобы сохранить файл в «Файлы», облачный диск или отправить себе.
- **Загрузка:** импорт из файла JSON с предварительной проверкой структуры и версии формата. Перед заменой данных показать предупреждение и предложить режим «заменить все данные».
- Формат файла имеет номер версии для будущей совместимости.
- Фотографии чеков (см. 4.11) по умолчанию в резервную копию не включаются, чтобы файл оставался небольшим. Пользователь может выбрать выгрузку «с фотографиями» (архив ZIP).

### 4.8. Напоминание о резервной копии
- Приложение хранит дату последней успешной выгрузки.
- При открытии приложения, если с момента последней выгрузки прошло более N дней (по умолчанию 7), на главном экране показывается заметный баннер с кнопкой «Сделать копию сейчас».
- Периодичность (N дней) и отключение напоминания настраиваются в разделе «Настройки».
- Если выгрузка ни разу не выполнялась, баннер показывается после первой недели использования.

### 4.9. Повторяющиеся платежи
- Платёж создаётся один раз и автоматически формирует операции в каждом расчётном периоде.
- Поля: название, сумма, валюта, категория, периодичность (еженедельно, ежемесячно, ежегодно, свой интервал), день платежа, дата начала.
- **Срок действия:**
  - с окончанием — по дате окончания или по количеству платежей (например, кредит);
  - бессрочный — без даты окончания (например, аренда, подписки, зарплата).
- Для платежей с окончанием показывается число оставшихся платежей и оставшаяся сумма.
- Автоматически создаются как расходы, так и доходы (например, зарплата в тенге).
- Платёж можно изменить с указанной даты, приостановить или завершить досрочно. Ранее созданные операции не изменяются.
- Если приложение не открывалось несколько дней, при следующем запуске создаются все пропущенные операции за этот период.

### 4.10. Календарь платежей
- Календарный вид месяца с отметкой дней, в которые предстоят платежи (кредиты, кружки, подписки, аренда и другие повторяющиеся платежи, а также разовые запланированные платежи).
- Список ближайших платежей на главном экране: на ближайшие 7 дней, с суммами и общим итогом.
- Разовые запланированные платежи можно добавлять вручную (например, оплата кружка, страховка).
- Напоминания: баннер на главном экране о платежах на сегодня и завтра при открытии приложения.
- Выгрузка платежей в файл календаря (.ics) для импорта в системный календарь телефона, чтобы напоминания приходили независимо от приложения. Это обходит ограничение PWA: надёжные уведомления по расписанию без сервера, особенно на iPhone, не гарантируются.

### 4.11. Быстрый ввод, фотографии и импорт из чата
- **Быстрый ввод:** с главного экрана расход вносится за три касания: выбор категории, ввод суммы, сохранение. Валюта, дата (сегодня) и счёт подставляются по умолчанию и меняются при необходимости.
- **Фотография чека:** к любой операции можно приложить фото (с камеры или из галереи). Изображение сжимается (длинная сторона около 1280 пикселей) и хранится локально в IndexedDB.
- **Импорт из чата:** кнопка «Импорт из чата» принимает текст в заданном формате JSON (одна или несколько покупок: дата, магазин, валюта, список позиций с названием, количеством, единицей, ценой, суммой и категорией) и создаёт операции после предварительного просмотра и подтверждения. В окне просмотра пользователь может исправить категорию, название и количество любой позиции.
- Кнопка «Скопировать инструкцию для Claude» копирует готовый текст запроса: описание формата, актуальный список категорий и справочник продуктов пользователя. Это нужно, чтобы названия и категории в чате совпадали с приложением. Пользователь вставляет текст в чат вместе с фотографией чека; Claude разбирает чек на позиции, уточняет у пользователя неясные позиции и выдаёт данные в нужном формате для вставки в приложение.
- Названия на чеке (в том числе сокращённые, на испанском языке) приводятся к названиям из справочника продуктов на русском языке; новые продукты добавляются в справочник при импорте после подтверждения.
- Распознавание чека внутри приложения (через API) в первую версию не входит.

### 4.12. Продукты, отчёты по продуктам и прогноз закупок
- **Справочник продуктов:** единое название продукта (например, «Лук репчатый»), основная единица измерения, категория по умолчанию. Возможность объединять дубликаты (например, «Лук», «Лук репчатый»).
- **Отчёт по продуктам за месяц:** что куплено, в каком количестве и на какую сумму; сортировка по сумме и по количеству; средняя цена за единицу; сравнение с прошлыми месяцами. Пример: «Лук репчатый — 2 кг, 2,40 €».
- **Отчёт по категории:** внутри категории (например, «Продукты») разбивка по продуктам.
- **История цены продукта:** изменение цены за единицу по датам и магазинам.
- **Прогноз закупок на следующий месяц:** на основе фактических покупок за предыдущие месяцы (по умолчанию за последние 3, настраивается) формируется ожидаемый перечень продуктов с количеством и ориентировочной стоимостью. Расчёт — среднее потребление за месяц по каждому продукту, для редко покупаемых продуктов — с учётом периодичности покупок.
- Прогноз сравнивается с лимитом категории: итоговая ожидаемая сумма и разница с лимитом.
- Перечень закупок можно отредактировать (убрать позиции, изменить количество), отметить купленное и скопировать списком для отправки в мессенджер.
- Если данных меньше двух месяцев, прогноз помечается как предварительный.

### 4.13. Экспорт для анализа и контроль избыточных покупок
- Все позиции всех покупок хранятся без ограничения срока и входят в резервную копию. Справочник продуктов и история цен сохраняются.
- **Экспорт для анализа:** кнопка выгружает файл CSV (кодировка UTF-8) с одной строкой на каждую позицию покупки. Столбцы: дата, магазин, продукт, категория, количество, единица, цена за единицу, сумма в исходной валюте, валюта, сумма в евро, идентификатор покупки. Можно выбрать период (месяц, 3 месяца, всё время).
- Вместе с файлом кнопка «Скопировать запрос для Claude» копирует готовый текст запроса на анализ: на что уходит больше всего денег, какие продукты покупаются чаще или в большем количестве, чем обычно, где выросла цена, что можно сократить, прогноз закупок на следующий месяц.
- **Отметка «выброшено / не съедено»:** к позиции покупки можно по желанию добавить количество, которое не было использовано (например, «выброшено полбатона»). Эти данные включаются в экспорт и учитываются в прогнозе закупок.
- **Подсказка в приложении:** если продукт куплен в этом месяце в заметно большем количестве, чем в среднем за предыдущие месяцы (порог настраивается, по умолчанию на 30 % больше), он отмечается значком в отчёте по продуктам.

### 4.14. Список желаемых покупок
- Отдельный раздел для вещей, которые пользователь хочет купить (одежда, предметы для дома, подарки, поездки и другое). Не связан со списком закупок продуктов из 4.12.
- Поля записи: название, фотография, ссылка (например, на публикацию в Instagram или страницу магазина), ориентировочная цена и валюта (EUR / KZT), категория, приоритет (высокий / средний / низкий), комментарий, статус.
- Статусы: «Хочу», «Запланировано на месяц», «Куплено».
- Фотография прикладывается из галереи или с камеры (например, снимок экрана публикации). Ссылка сохраняется как текст и открывается по нажатию; автоматическая подгрузка превью по ссылке не предусмотрена, потому что внешние сайты (в том числе Instagram) не отдают содержимое приложению.
- Фильтры и сортировка: по приоритету, категории, цене, дате добавления. В заголовке раздела показывается общая ориентировочная сумма в евро по выбранному фильтру.
- **Связь с бюджетом:** при составлении бюджета месяца рядом отображается список желаемых покупок. Выбранные записи одним действием переносятся в плановые расходы бюджета с их категорией и суммой, а статус меняется на «Запланировано на месяц». Плановая сумма учитывается в лимите категории.
- **Покупка:** при отметке «Куплено» приложение создаёт фактический расход с предзаполненными полями (сумма, категория, название), которые можно скорректировать; запись остаётся в разделе в статусе «Куплено» с датой покупки и фактической ценой.
- Записи, фотографии и ссылки входят в резервную копию по тем же правилам, что и остальные данные (фотографии — только при выгрузке «с фотографиями»).
- Необязательная возможность для Android: приём ссылок и изображений из меню «Поделиться» других приложений (Web Share Target API), чтобы добавлять записи прямо из Instagram. На iPhone эта функция не поддерживается, там запись создаётся вручную внутри приложения.

## 5. Нефункциональные требования

- Работа полностью без интернета, кроме получения курса.
- Данные не передаются третьим лицам; запросы во внешние сервисы только для получения курсов.
- Быстрое добавление операции: не более трёх касаний от главного экрана.
- Корректная работа в светлой и тёмной теме системы.
- Точность денежных расчётов: суммы хранятся в минимальных единицах (центы, тиыны) или с использованием десятичной арифметики, без ошибок округления чисел с плавающей запятой.

## 6. Известные ограничения первой версии

- Нет автоматической синхронизации между устройствами. Перенос данных выполняется через файл резервной копии.
- Данные хранятся в браузере устройства; очистка данных сайта или удаление приложения приведёт к их потере, поэтому важна регулярная выгрузка.
- Возможная доработка в будущем: облачное хранение и вход в аккаунт.

## 7. Критерии приёмки

1. Приложение устанавливается на домашний экран и открывается без интернета.
2. Можно добавить расход в евро и доход в тенге; доход пересчитывается в евро по курсу Нацбанка на дату операции.
3. Курс можно изменить вручную.
4. Лимит категории показывает остаток и предупреждает при 80 % и 100 %.
5. Бюджет прошлого месяца копируется в новый месяц одним действием.
6. Выгрузка создаёт файл JSON, загрузка полностью восстанавливает данные на чистом устройстве.
7. При отсутствии выгрузки более 7 дней на главном экране появляется напоминание.
8. После сохранения расхода показывается остаток лимита категории и сумма «можно тратить в день».
9. Можно создать повторяющийся платёж с датой окончания (кредит) и без неё; операции создаются автоматически, в том числе пропущенные.
10. Календарь платежей показывает ближайшие платежи, а выгрузка в .ics открывается в календаре телефона.
11. К операции можно приложить фото чека; данные из чата импортируются в приложение через кнопку импорта.
12. Покупка из 10 позиций с разными категориями сохраняется одной операцией; расходы по лимитам распределяются по категориям позиций.
13. Отчёт по продуктам показывает количество и сумму по каждому продукту за выбранный месяц.
14. Прогноз закупок формирует перечень продуктов с количеством и стоимостью на следующий месяц и сравнивает итог с лимитом.
15. Экспорт для анализа создаёт файл CSV со всеми позициями за выбранный период; запрос для Claude копируется одной кнопкой.
16. Продукты, купленные в количестве выше среднего, отмечаются в отчёте по продуктам; к позиции можно добавить отметку о выброшенном количестве.
17. В список желаемых покупок можно добавить запись с фото, ссылкой и ценой; при составлении бюджета запись переносится в плановые расходы, а при отметке «Куплено» создаётся фактический расход.

## 8. Этапы реализации

1. Каркас PWA: манифест, сервис-воркер, локальная база, навигация.
2. Операции и категории.
3. Валюты и курсы Нацбанка (включая проверку доступности источника).

## Журнал

### 2026-10-18 — этап 1

Решение по стеку: без Node.js и инструментов сборки — обычные HTML, CSS и JavaScript-модули (вариант А, выбран пользователем). Локальный запуск через Python (`python3 -m http.server`). Тесты выполняются страницей `tests/` в браузере.

Сделано:
- оболочка приложения с пятью разделами (Главная, Операции, Бюджет, Отчёты, Ещё), светлая и тёмная темы;
- манифест и иконки для установки на домашний экран (iOS и Android);
- сервис-воркер: приложение открывается без интернета (проверено: при остановленном сервере страница загружается из кэша);
- локальная база IndexedDB с версионируемой схемой и миграциями (пока одна таблица `settings`);
- тесты базы: 6 проверок, все проходят.

Не проверено: установка на домашний экран и работа без интернета на реальном телефоне (требует публикации на GitHub Pages — этап 10, либо ранее по решению пользователя).

- для каждой операции хранится курс и сумма в евро; для тенге без курса — статус «курс не определён» (курс появится на этапе 3);

### 2026-10-18 — этап 3

**Проверка источника (п. 4.5 ТЗ).** Сайт Нацбанка отдаёт курсы (`https://nationalbank.kz/rss/get_rates.cfm?fdate=ДД.ММ.ГГГГ`, XML, курс EUR на любую дату), но прямые запросы из браузера блокируются: сервер не присылает заголовок CORS. Предложены два решения (файл курсов, обновляемый через GitHub Actions; посредник Cloudflare Worker).

**Изменение ТЗ по решению пользователя (2026-10-18):** автоматическое получение курса Нацбанка не реализуется, курс вводится вручную. Внешних запросов у приложения теперь нет. Автоматическое получение можно добавить позже одним из предложенных способов без переделки структуры данных.

Сделано:
- миграция базы № 3: таблица курсов по датам;
- форма операции: при выборе ₸ появляется поле «Курс, ₸ за 1 €» с живым пересчётом в евро; подставляется курс на эту дату, иначе ближайший предыдущий известный;
- введённый курс запоминается на дату; операции в тенге за ту же дату без курса пересчитываются автоматически (приложение сообщает, к скольким операциям применён курс);
- операция в тенге без курса сохраняется со статусом «курс не определён» и не входит в итоги;
- в списке операций в тенге показана сумма в евро и курс;
- тесты курсов: 3 проверки; всего 25, все проходят.

Покупка без позиций по-прежнему вводится одной суммой. Добавлено поле «Магазин». Сообщение о лимите после покупки выводится по каждой затронутой категории с лимитом.

**Быстрый ввод (три касания)**: на главной — категории расходов кнопками; касание категории → поле суммы → «Сохранить» (или Enter); евро, сегодняшняя дата; после сохранения показывается сообщение по лимиту.

**Фото чека**: в форме операции «Снять или выбрать» (камера или галерея на телефоне), сжатие до 1280 px, хранение в базе, удаление вместе с операцией; в списке операций отметка 📷.

Принимаются: объект { purchases: [...] }, массив покупок, одна покупка, JSON внутри блока ```json```; единицы в испанских/английских сокращениях (ud, uds, kg, g, l) приводятся к русским; сумма позиции при отсутствии считается как цена × количество.

### 2026-10-18 — этап 8

Сделано:

**Справочник продуктов** («Ещё» → «Продукты»): список с поиском; карточка продукта — название, основная единица, категория по умолчанию (переименование обновляет названия в позициях покупок); объединение дубликатов (все позиции переходят к выбранному продукту); история покупок и цен за единицу по датам и магазинам; отметка «выброшено / не съедено» у каждой покупки. Позиции, введённые вручную в форме операции, тоже привязываются к справочнику.

**Отчёт по продуктам** («Отчёты» → «Отчёт по продуктам»; месяц переключается): что куплено, количество, сумма, средняя цена за единицу, количество за предыдущий месяц; сортировка по сумме и по количеству; вид «По категориям» — разбивка по продуктам внутри категории; значок ⚠ — продукт куплен на N % больше среднего за прошлые месяцы (порог настраивается, по умолчанию 30).

**Прогноз закупок** («Отчёты» → «Прогноз закупок»): перечень на следующий месяц по последним N месяцам (по умолчанию 3, настраивается): среднее потребление в месяц за вычетом выброшенного, стоимость по средней цене; для редких продуктов — «примерно раз в X мес.»; сравнение с лимитами категорий целевого месяца и итог; перечень редактируется (количество, удаление), покупки отмечаются, список копируется для мессенджера; при данных меньше двух месяцев помечен как предварительный.

**Экспорт для анализа** (на экране отчёта по продуктам): CSV UTF-8 с BOM, одна строка на позицию (дата, магазин, продукт, категория, количество, единица, цена за единицу, сумма, валюта, сумма в евро, выброшено, id покупки), период — месяц / 3 месяца / всё время; через «Поделиться» или скачивание; кнопка «Скопировать запрос» — текст запроса на анализ для Claude.

Тесты: сводки по продуктам, история цен, прогноз (включая выброшенное и редкие продукты, признак предварительности), CSV, переименование/объединение/отметка «выброшено»; всего 63, все проходят.

### 2026-10-18 — этап 9

Сделано:

**Резервная копия** («Ещё» → «Резервная копия»):
- выгрузка всех данных (настройки, категории, операции с позициями, курсы, бюджеты, повторяющиеся и разовые платежи, желаемые покупки, продукты) в один файл `finance-backup-ГГГГ-ММ-ДД.json`; формат имеет номер версии (`format: finance-backup`, `version: 1`) и версию схемы базы; через системное меню «Поделиться», иначе скачивание;
- копия «с фотографиями» — ZIP (`backup.json` + `photos/<id>.jpg`), собранный своим кодом без внешних библиотек;
- загрузка: выбор файла .json или .zip → проверка структуры и версии до изменения данных (формат, версия не новее поддерживаемой, разделы-списки, ключи записей, целые суммы и даты у операций) → сводка содержимого и предупреждение → «Заменить все данные» с подтверждением. Без архива сохраняются только фотографии, на которые ссылаются загружаемые записи. Дата последней копии и дата установки устройства при восстановлении не перезаписываются.

**Напоминание** (п. 4.8): хранится дата последней успешной выгрузки; баннер на главной «Сделать копию сейчас», если прошло больше N дней (по умолчанию 7); если копия ни разу не делалась — после первой недели использования. «Ещё» → «Настройки»: периодичность и отключение напоминания (там же — настройки прогноза закупок).

Тесты: ZIP (запись, чтение, CRC-32, повреждённый архив), проверка файла, полный круг выгрузка → чистая база → восстановление, копия с фотографиями, правило напоминания; всего 69, все проходят. Меню «Поделиться» проверяется на телефоне.

Изучены разборы Monefy, Fleur, EveryDollar, Budget app, SubPilot, Spendee (Screensdesign, обзоры) и подборка на Dribbble. Добавлено (без новых функций учёта, тесты не затронуты, 69 проходят):
1. На главной: «Можно сегодня» (остаток по всем лимитам ÷ дни до конца месяца) и «Осталось по лимитам».

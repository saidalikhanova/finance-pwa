## Журнал

### 2026-10-18 — этап 1

Решение по стеку: без Node.js и инструментов сборки — обычные HTML, CSS и JavaScript-модули (вариант А, выбран пользователем). Локальный запуск через Python (`python3 -m http.server`). Тесты выполняются страницей `tests/` в браузере.

Сделано:
- оболочка приложения с пятью разделами (Главная, Операции, Бюджет, Отчёты, Ещё), светлая и тёмная темы;
- манифест и иконки для установки на домашний экран (iOS и Android);
- сервис-воркер: приложение открывается без интернета (проверено: при остановленном сервере страница загружается из кэша);
- локальная база IndexedDB с версионируемой схемой и миграциями (пока одна таблица `settings`);
- тесты базы: 6 проверок, все проходят.

Не проверено: установка на домашний экран и работа без интернета на реальном телефоне (требует публикации на GitHub Pages — этап 10, либо ранее по решению пользователя).

### 2026-10-18 — этап 2

Сделано:
- операции: добавление, редактирование, удаление; поля — тип, сумма, валюта (EUR/KZT), дата, категория, комментарий; суммы хранятся целыми числами (центы, тиыны);
- для каждой операции хранится курс и сумма в евро; для тенге без курса — статус «курс не определён» (курс появится на этапе 3);
- список операций по месяцам с фильтрами по типу и категории, итоги месяца в евро;
- категории: набор по умолчанию при первом запуске, добавление, переименование, архивирование (удаление не предусмотрено по ТЗ); в разделе «Ещё»;
- миграция базы № 2 (таблицы категорий и операций);
- тесты: деньги и пересчёт, категории, операции — всего 22 проверки, все проходят.

Трактовка ТЗ: позиции покупки (чек) будут добавлены на этапах 7–8 вместе со справочником продуктов; структура операции уже содержит поле `items`.

### 2026-10-18 — этап 3

**Проверка источника (п. 4.5 ТЗ).** Сайт Нацбанка отдаёт курсы (`https://nationalbank.kz/rss/get_rates.cfm?fdate=ДД.ММ.ГГГГ`, XML, курс EUR на любую дату), но прямые запросы из браузера блокируются: сервер не присылает заголовок CORS. Предложены два решения (файл курсов, обновляемый через GitHub Actions; посредник Cloudflare Worker).

**Изменение ТЗ по решению пользователя (2026-10-18):** автоматическое получение курса Нацбанка не реализуется, курс вводится вручную. Внешних запросов у приложения теперь нет. Автоматическое получение можно добавить позже одним из предложенных способов без переделки структуры данных.

Сделано:
- миграция базы № 3: таблица курсов по датам;
- форма операции: при выборе ₸ появляется поле «Курс, ₸ за 1 €» с живым пересчётом в евро; подставляется курс на эту дату, иначе ближайший предыдущий известный;
- введённый курс запоминается на дату; операции в тенге за ту же дату без курса пересчитываются автоматически (приложение сообщает, к скольким операциям применён курс);
- операция в тенге без курса сохраняется со статусом «курс не определён» и не входит в итоги;
- в списке операций в тенге показана сумма в евро и курс;
- тесты курсов: 3 проверки; всего 25, все проходят.

### 2026-10-18 — этап 4

Сделано:
- миграция базы № 4: таблица бюджета (на месяц и категорию: план и лимит в евро);
- экран «Бюджет»: месяц со стрелками; итоги план/факт по доходам, расходам и балансу; по каждой категории расходов — факт, лимит, процент использования с полосой, остаток и «можно тратить в день»; предупреждение при 80 % (оранжевый) и при превышении (красный); по доходам — факт и план;
- нажатие на категорию открывает форму «План и лимит» (у доходов — только план);
- копирование бюджета из любого месяца одним действием (с подтверждением, если в целевом месяце бюджет уже есть);
- после сохранения расхода показывается сообщение по лимиту категории в формате ТЗ: «Продукты: осталось 143,00 € из 200,00 €, до конца месяца 14 дней, около 10,21 € в день»; при превышении — красное;
- тесты лимитов (4) и бюджета (3); всего 32, все проходят.

Дополнение к ТЗ по просьбе пользователя: экран «Ещё» → «Курсы тенге к евро» — история введённых курсов по датам; курс можно добавить, изменить и удалить.

Для разработки: сервер `scripts/serve.py` отдаёт файлы без кэширования (иначе браузер показывал старые версии после правок).

### 2026-10-18 — этап 6

Сделано (миграция базы № 5: таблицы платежей, разовых платежей, желаемых покупок, фотографий):

**Повторяющиеся платежи** («Ещё» → «Платежи»): название, сумма, валюта, категория, периодичность (еженедельно, ежемесячно, ежегодно, свой интервал в днях), дата первого платежа, срок (бессрочно, до даты, число платежей). Операции создаются автоматически при открытии приложения, включая пропущенные за дни без запуска; для тенге подставляется известный курс. Для платежей с окончанием показаны оставшиеся платежи и сумма. Приостановка (пропущенные за паузу не создаются), возобновление, досрочное завершение, удаление; изменение действует со следующего платежа, созданные операции не меняются.

**Разовые платежи и календарь**: разовый платёж — напоминание; кнопка «Оплачено» открывает форму операции с заполненными полями (трактовка ТЗ). Календарь месяца с отметками дней и списком платежей на выбранный день. На главной — баннер о платежах сегодня и завтра и список на 7 дней с итогом. Выгрузка .ics на 12 месяцев через «Поделиться» или скачивание.

**Желаемые покупки** («Ещё» → «Желаемые покупки»): название, фото (сжатие до 1280 px, хранится в базе), ссылка, цена и валюта, категория, приоритет, комментарий; статусы «Хочу / В плане / Куплено»; сортировка по приоритету, цене, дате, категории; фильтр по категории; в шапке — сумма в евро. В «Бюджете» — блок желаемых покупок: отмеченные переносятся в план категории одним действием. Кнопка «Куплено — записать расход» создаёт расход с заполненными полями; запись получает дату и фактическую цену.

Не включено: приём ссылок из других приложений на Android (необязательный пункт ТЗ). Фото проверялись тестами, без ручной загрузки файла в браузере.

Тесты: повторяющиеся платежи (9, включая пропущенные периоды, окончание по числу и дате, паузу), разовые платежи, календарь, .ics, желаемые покупки (4); всего 49, все проходят.

### 2026-10-18 — этап 7

Сделано (миграция базы № 6: справочник продуктов — минимальная таблица, экраны справочника в этапе 8):

**Покупка с позициями (п. 4.1)**: в форме операции раздел «Позиции (чек)» — название, количество (до 3 знаков), единица (кг, г, л, мл, шт, уп), сумма, категория каждой позиции; сумма операции считается по позициям; лимиты, бюджет и отчёты учитывают категорию каждой позиции (разница округления при пересчёте тенге относится на последнюю позицию, итог сходится). Покупка без позиций по-прежнему вводится одной суммой. Добавлено поле «Магазин». Сообщение о лимите после покупки выводится по каждой затронутой категории с лимитом.

**Быстрый ввод (три касания)**: на главной — категории расходов кнопками; касание категории → поле суммы → «Сохранить» (или Enter); евро, сегодняшняя дата; после сохранения показывается сообщение по лимиту.

**Фото чека**: в форме операции «Снять или выбрать» (камера или галерея на телефоне), сжатие до 1280 px, хранение в базе, удаление вместе с операцией; в списке операций отметка 📷.

**Импорт из чата** («Операции» → «Импорт из чата», также в «Ещё»): кнопка «Скопировать инструкцию для Claude» — текст с правилами, форматом JSON, списком категорий расходов и справочником продуктов; поле для JSON, «Разобрать» → предпросмотр: дата, магазин и позиции редактируются, неизвестные категории подсвечены; «Создать операции» создаёт покупки и (по флагу) новые продукты в справочнике, позиции привязываются к продуктам. Принимаются: объект { purchases: [...] }, массив покупок, одна покупка, JSON внутри блока ```json```; единицы в испанских/английских сокращениях (ud, uds, kg, g, l) приводятся к русским; сумма позиции при отсутствии считается как цена × количество.

Тесты: позиции (4), импорт (5); всего 58, все проходят. Загрузка фото с камеры проверяется на телефоне.

### 2026-10-18 — этап 8

Сделано:

**Справочник продуктов** («Ещё» → «Продукты»): список с поиском; карточка продукта — название, основная единица, категория по умолчанию (переименование обновляет названия в позициях покупок); объединение дубликатов (все позиции переходят к выбранному продукту); история покупок и цен за единицу по датам и магазинам; отметка «выброшено / не съедено» у каждой покупки. Позиции, введённые вручную в форме операции, тоже привязываются к справочнику.

**Отчёт по продуктам** («Отчёты» → «Отчёт по продуктам»; месяц переключается): что куплено, количество, сумма, средняя цена за единицу, количество за предыдущий месяц; сортировка по сумме и по количеству; вид «По категориям» — разбивка по продуктам внутри категории; значок ⚠ — продукт куплен на N % больше среднего за прошлые месяцы (порог настраивается, по умолчанию 30).

**Прогноз закупок** («Отчёты» → «Прогноз закупок»): перечень на следующий месяц по последним N месяцам (по умолчанию 3, настраивается): среднее потребление в месяц за вычетом выброшенного, стоимость по средней цене; для редких продуктов — «примерно раз в X мес.»; сравнение с лимитами категорий целевого месяца и итог; перечень редактируется (количество, удаление), покупки отмечаются, список копируется для мессенджера; при данных меньше двух месяцев помечен как предварительный.

**Экспорт для анализа** (на экране отчёта по продуктам): CSV UTF-8 с BOM, одна строка на позицию (дата, магазин, продукт, категория, количество, единица, цена за единицу, сумма, валюта, сумма в евро, выброшено, id покупки), период — месяц / 3 месяца / всё время; через «Поделиться» или скачивание; кнопка «Скопировать запрос» — текст запроса на анализ для Claude.

Тесты: сводки по продуктам, история цен, прогноз (включая выброшенное и редкие продукты, признак предварительности), CSV, переименование/объединение/отметка «выброшено»; всего 63, все проходят.
